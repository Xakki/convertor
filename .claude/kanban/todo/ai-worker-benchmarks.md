### AI-воркер — бенчмарки по эндпойнтам + persistent volume с моделями/тестами/ожиданиями

**Критичность:** Medium

**TAGS:**
- feature
- dx

**Описание:**
Раздельный запуск бенчмарков по разным методам конвертации (STT/TTS/embedding/LLM),
каждый — со своим конфигом и статистикой, через web UI dev-сервера. Все данные
бенчмарков (наборы моделей, тест-файлы, ожидаемые результаты, прогоны/статистика)
хранятся на **не стираемом volume**, который можно пробросить в соседнюю директорию
при запуске контейнера.

Зависит от [[ai-worker-refactor-core]]; UI-вкладка живёт в [[ai-worker-devserver]].
Развивает существующий `workers/ai/bench/` (runner/metrics/report уже есть).

**Проблема:**
- `bench/` не интегрирован в общий тулинг и не хранит данные на отдельном volume —
  нельзя удобно править модели/тест-файлы/ожидаемое и сохранять результаты между
  пересозданиями контейнера.
- Нет раздельного по-эндпойнтного запуска со своей статистикой из UI.

**Рекомендация:**
1. `bench/store.py` — чтение/запись бенч-данных на volume `BENCH_DATA_DIR`. Раскладка:
   ```
   <BENCH_DATA_DIR>/
   ├── suites/{stt,tts,embedding,llm}.yaml   # модели + кейсы (вход + ожидаемое) + параметры
   ├── inputs/                                # тест-файлы (audio/text/…)
   └── results/<suite>/<runId>.json           # выводы прогонов + статистика (append-only)
   ```
2. Раздельные suites по эндпойнтам — у каждого свой набор моделей, кейсов и параметров.
3. `runner.py` исполняет выбранный suite, считает метрики (WER/CER/similarity и т.п. —
   уже в `metrics.py`), пишет результат в `results/` (не стирается).
4. UI-вкладка Benchmarks (в dev-сервере): выбрать suite → запустить → по-кейсовые метрики
   + агрегат; редактировать модели/тест-файлы/ожидаемое (правка YAML на volume через UI).
5. Volume пробрасывается соседней папкой: `docker run -v ./bench-data:/data/bench`
   (`BENCH_DATA_DIR=/data/bench`).

**Влияние:**
Воспроизводимая оценка качества/скорости моделей; данные переживают пересоздание
контейнера и шарятся через bind в соседнюю папку.

**Критерии приёмки:**
- `bench/store.py` читает/пишет раскладку suites/inputs/results на `BENCH_DATA_DIR`.
- Раздельный запуск бенчмарка по каждому эндпойнту со своим конфигом и статистикой.
- Результаты прогонов сохраняются (append-only) и переживают пересоздание контейнера.
- Из UI можно добавить/поменять модель, тест-файл и ожидаемый результат.
- `pytest workers/tests` зелёный (store + runner покрыты на мелких кейсах).

**Decisions:**
- Данные бенчей — на отдельном volume `BENCH_DATA_DIR`, bind в соседнюю папку при `docker run`.
- Формат конфигов — YAML (suites), результаты — JSON (append-only по runId).
