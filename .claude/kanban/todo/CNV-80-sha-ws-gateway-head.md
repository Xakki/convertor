### Сверять SHA образа запущенного ws-gateway с HEAD

**Criticality:** Medium

**TAGS:**
- tech-debt

**Description:**
Во время CNV-71 `ws-gateway` дважды работал со старым образом, хотя нужный код
уже был в текущем HEAD. Существующий `gateway-verify-code` проверяет только
конкретный исходный маркер и не доказывает соответствие образа репозиторию.

**Problem:**
Нет дешёвого воспроизводимого способа сверить git SHA запущенного gateway с HEAD.

**Impact:**
Проверки и диагностика могут выполняться на устаревшем коде, маскируя результат
как дефект реализации или окружения.

**Recommendation:**
Запекать и печатать git short SHA при старте `ws-gateway`; добавить read-only
`make gateway-verify-sha`, который извлекает SHA из запущенного контейнера и
сравнивает с `git rev-parse --short HEAD`, возвращая ненулевой код при расхождении.

**Acceptance Criteria:**
- Образ gateway получает git short SHA во время build и пишет его в startup-лог.
- `make gateway-verify-sha` не модифицирует контейнер и сообщает локальный HEAD,
  SHA контейнера и понятный результат сравнения.
- Таргет завершается успешно при совпадении и ошибкой при расхождении; покрыт
  автоматической проверкой либо изолированным тестом Makefile-логики.
- Тесты/QA green: pytest; make test; make build.

**Decisions:**
- 2026-08-14: выбран startup-лог SHA вместе с `make gateway-verify-sha`;
  решение выделено из п.2 CNV-73.
