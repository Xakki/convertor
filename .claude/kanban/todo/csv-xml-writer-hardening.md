### CSV-writer / XML-reader hardening — корректный `*→csv` для всех источников

**Критичность:** Medium

**TAGS:**
- bug
- tech-debt

**Описание:**
Валидация матрицы data-воркера (`workers/data/worker.py`, через S3 на реальном MinIO,
задача [[validate-data-worker]] 2026-06-20) вскрыла пред-существующие дефекты в
CSV-writer и XML-reader. Они не связаны с toml-изменением (не введены и не ухудшены им),
но делают часть пар `*→csv` некорректными — молчаливая потеря данных.

**Проблема:**
- `*→csv`: writer оставляет только первое list-значное поле и роняет соседние скаляры.
  Реально воспроизведено: `json→csv` теряет `project`/`version`, `toml→csv` теряет
  `title`/`owner`. Источник — `_write_data` ищет список записей лишь на одном уровне.
- `xml→csv` вырожден: `_read_data` возвращает `{root: {...}}`, а CSV-writer сканирует
  только один уровень и не находит список записей → результат 1×1 ячейка со
  стрингифицированным dict. Для реального XML непригодно.
- XML-числа теряют тип (`price → "10"`): `_read_data` для XML отдаёт всё строками.

**Влияние:**
Пользователь, конвертирующий json/toml/yaml/xml → csv с несколькими полями верхнего
уровня или с реальной XML-структурой, молча получает неполный/битый CSV. Затрагивает
весь столбец `*→csv` матрицы данных, не только toml.

**Решение (набросок):**
- Привести CSV-writer к единому контракту: на вход — список записей (list[dict]);
  если данные — dict с единственным list-полем, разворачивать его; если плоский dict —
  одна строка. Заголовок = объединение ключей всех записей.
- Для `xml→csv` согласовать форму, которую отдаёт XML-reader (`{root: {...}}`), с тем,
  что ожидает writer (найти повторяющийся дочерний элемент как список записей).
- Решить по типам XML (числа/булевы): аккуратная коэрция или явно задокументировать,
  что XML→* отдаёт строки.

**Критерии приёмки:**
- `json→csv`, `toml→csv`, `yaml→csv` сохраняют все поля верхнего уровня (round-trip без
  потери колонок на реальном датасете).
- `xml→csv` даёт осмысленный табличный результат на реальном XML с повторяющимися
  элементами.
- Unit-тесты на каждую `*→csv` пару (включая multi-field и xml-with-repeats); `pytest
  workers/tests` зелёный; `make docker-check` проходит.

**Decisions:**
- Выделено из [[validate-data-worker]] при валидации матрицы 2026-06-20 (решение
  пользователя — отдельной карточкой, не блокирует закрытие data-воркера).
