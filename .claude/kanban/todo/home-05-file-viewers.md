### Инлайн-превью результатов конвертации (audio/video/image/text/PDF)

**Criticality:** Medium

**TAGS:**
- feature
- frontend
- security

**Description:**
Часть эпика [[home-00-epic]]. Выполняется после [[home-04-format-info-
examples]] — переиспользует те же примеры из S3 для демонстрации вьюеров, и
сами вьюеры, добавленные здесь, применяются и к обычным пользовательским
результатам конвертации (не только к примерам).

Сейчас на `conversion/index.html.twig` есть ТОЛЬКО текстовое превью (модалка,
≤64KB, через `x-text` — см. `App\Controller\Api\ConversionController::
preview()`, `GET /api/v1/convert/{id}/preview`, отдаёт `text/plain` с
`X-Content-Type-Options: nosniff`, специально НЕ HTML — экранирование на
фронте). Никаких других медиапревью нет.

**⚠️ КРИТИЧНОЕ ограничение (XSS-safety, из решения D4):** для текстовых
результатов ОБЯЗАТЕЛЬНО сохранить существующий XSS-safe подход — вставка
через Alpine `x-text` (не `x-html`, не `innerHTML`), лимит ≤64KB (как уже
отдаёт `/preview`), НИКАКОГО HTML-инъекшена контента результата в DOM. Это
не предложение, а жёсткое требование — результат конвертации это
непроверенные байты пользователя/воркера, downstream XSS исключается ТОЛЬКО
безопасной вставкой.

**Problem:**
Пользователь может только скачать результат или увидеть усечённый текст —
для аудио/видео/изображений/PDF нет способа посмотреть результат прямо на
странице, приходится скачивать файл, чтобы проверить, что конвертация
получилась.

**Impact:**
Лишний шаг для проверки результата; хуже воспринимаемое качество сервиса
по сравнению с конкурентами, у которых есть инлайн-предпросмотр.

**Recommendation:** LIGHT MVP по решению D4 (см. [[home-00-epic]]) — НЕ
делать полноценный document-viewer (без server-side рендеринга docx/xlsx/
pptx/odt в HTML/картинки):
- **audio/video** → нативные HTML5 `<audio controls>` / `<video controls>` с
  `src`, указывающим на presigned/скачиваемый URL результата (переиспользовать
  существующий `GET /api/v1/convert/{id}/download` или отдельный presign,
  сверить с `backend-architecture`, как сейчас реализована выдача файла —
  redirect на presigned URL или проксирование байт через Symfony).
- **image** → инлайн-попап (модалка) с `<img>`, `src` — presigned URL или
  object URL из уже скачанных байт (`Blob` → `URL.createObjectURL`),
  аккуратно отзывать (`revokeObjectURL`) при закрытии модалки, чтобы не
  текла память.
- **text** → существующий попап с `x-text`, ≤64KB, БЕЗ изменений в
  безопасности — только визуально встроить в общий UI вьюеров, если меняется
  общий контейнер модалки.
- **PDF** → `<embed type="application/pdf">` или `<iframe>` на presigned URL
  результата (браузерный PDF-рендерер, никакого серверного рендеринга
  страниц в картинки).
- **Остальные документы** (docx/xlsx/pptx/odt/rtf/epub/…) → ТОЛЬКО кнопка
  «Скачать», БЕЗ инлайн-превью и БЕЗ серверного рендеринга — явно вне
  скоупа MVP.
- Определение, какой вьюер показать — по целевому формату (`to_format`
  задачи), маппинг категория→тип вьюера завести как небольшую константу на
  фронте (Alpine) либо получить `category` из `GET /api/v1/formats` по
  `to_format` (переиспользовать данные, уже используемые в
  [[home-03-conversion-variants]]).
- Прочитать skill `api-design` (эндпоинты `download`/`preview`/`source`,
  их коды ошибок 401/404/409/410/415 — обрабатывать в UI), `backend-
  architecture` (как результат оказывается доступен — presign vs proxy).

**Acceptance Criteria:**
- Результат с целевым форматом mp3/wav/ogg/… → инлайн `<audio>` плеер на
  странице.
- Результат mp4/webm/… → инлайн `<video>` плеер.
- Результат jpg/png/…  → попап с `<img>`.
- Текстовый результат → попап с `x-text` (НЕ `x-html`/`innerHTML`), ≤64KB —
  без изменений в безопасности относительно текущей реализации.
- Результат pdf → попап/секция с `<embed>`/`<iframe>` на presigned URL.
- Результат docx/xlsx/pptx/odt/… → ТОЛЬКО кнопка «Скачать», без попытки
  инлайн-рендера.
- Ни один вьюер не вставляет непроверенные байты результата как HTML/через
  `innerHTML`/`x-html` — ревью специально проверяет этот пункт.
- Ошибки от `preview`/`download`/`source` (401/404/409/410/415) показывают
  понятное сообщение пользователю, не «белый экран»/необработанное
  исключение в консоли.
- Tests/QA green: `make test`, `make phpstan`, `make cs-check`.

**Decisions:**
- D4 (см. [[home-00-epic]]): LIGHT MVP-разбивка по типам как описано выше —
  согласовано с пользователем, не открывать заново.
- Прочие документы (docx/xlsx/pptx/odt/…) — сознательно НЕ превьюятся в
  этой итерации; кнопка «Скачать» — единственное действие.
