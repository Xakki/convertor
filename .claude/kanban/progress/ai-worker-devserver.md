### AI-воркер — локальный dev-сервер (FastAPI) + web UI: тестер методов, аудио-стрим, pull-stats, настройки

**Критичность:** High

**TAGS:**
- feature
- dx

**Описание:**
Единый локальный FastAPI dev-сервер с web UI для ручной проверки всех методов
конвертации AI-воркера, live-теста потоковой обработки аудио из браузера, просмотра
статистики обработки реальных pull-задач и редактирования всех настроек воркера.
Запуск: `python -m workers.ai --devserver` (отдельно от прод-режима воркера).

Зависит от [[ai-worker-refactor-core]]; интегрирует бенчмарки из [[ai-worker-benchmarks]].

**Проблема:**
Сейчас методы конвертации проверяются только через реальную очередь/прод-воркер —
нет локального способа быстро прогнать метод на своём файле, посмотреть live-стрим
аудио, увидеть статистику pull-обработки или поменять настройку без правки env и
пересборки.

**Рекомендация:**
`devserver/` пакет: FastAPI-приложение, одностраничный web UI (Alpine.js + HTMX +
Tailwind по CDN, по правилам фронта проекта). Вкладки:
1. **Methods** — список всех доступных методов конвертации (из capabilities-матрицы),
   выбор source→target, загрузка файла (в `/tmp`), запуск, результат (превью/скачать).
2. **Audio stream** — захват микрофона в браузере → **WebSocket** на dev-сервер →
   live-транскрипт (потоковый STT, окна/overlap). НЕ завязан на backend pull-API —
   только локальный dev/тест.
3. **Pull stats** — статистика обработки реальных pull-задач с сервера, когда
   `PULL_ENABLED=true`: счётчики обработано/успех/ошибка, латентность, текущая задача,
   последние ошибки. Когда выключено — показывать состояние «обработка выключена».
4. **Settings** — просмотр и редактирование **всех доступных настроек** воркера из UI
   (включая тумблер `PULL_ENABLED` вкл/выкл обработки в рантайме). Изменения сохраняются
   на volume (переживают рестарт). Настройки делятся на:
   - **горячие** (применяются сразу: `PULL_ENABLED`, poll-интервал, параметры LLM-инференса);
   - **требующие перезагрузки модели/рестарта** (модель Whisper/embedding, бэкенд LLM) —
     помечать в UI «применится при следующем старте/задаче».

**Структура:**
```
workers/ai/devserver/
├── app.py            # FastAPI: сборка приложения, монтаж роутов и статики
├── routes_methods.py # POST: прогон любого метода (upload→/tmp→result)
├── routes_stream.py  # WS: потоковая обработка аудио
├── routes_stats.py   # GET: статистика pull-обработки
├── routes_settings.py# GET/PUT: чтение/правка настроек (persist на volume), toggle PULL_ENABLED
└── static/           # одностраничный web UI (вкладки)
```

**Влияние:**
Резко ускоряет проверку методов и моделей; даёт наблюдаемость pull-обработки и
управление настройками без правки env/пересборки.

**Критерии приёмки:**
- `python -m workers.ai --devserver` поднимает FastAPI с web UI (4 вкладки).
- Methods: можно выбрать метод, загрузить файл в `/tmp`, получить результат для всех
  доступных методов AI-воркера.
- Audio stream: браузер стримит микрофон по WS, виден live-результат; не трогает backend.
- Pull stats: при `PULL_ENABLED=true` показывает живую статистику; при `false` — «выключено».
- Settings: все настройки видны и редактируемы; тумблер `PULL_ENABLED` работает в рантайме;
  изменения persist на volume; помечены горячие vs требующие рестарта.
- `pytest workers/tests` зелёный (роуты покрыты, провайдеры мокаются где надо).

**Decisions:**
- Dev-сервер — единый FastAPI + web UI (а не разрозненные CLI-скрипты).
- Стриминг аудио — WS только на dev-сервере, вне backend pull-API/очередей.
- Управление обработкой и всеми настройками — через UI, с persist на volume.
- Безопасность dev-сервера: bind на `127.0.0.1` по умолчанию; опциональный bearer-токен
  для доступа по сети с GPU-хоста (не блокер, дефолт — только localhost).
