### Image options (`width`/`height`) валидируются, но не применяются к результату

**Criticality:** High

**TAGS:**
- feature
- image
- conversion-options
- worker
- data-flow

**Description:**
При загрузке изображения с параметрами ресайза (`options[width]` и `options[height]`) параметры валидируются в backend API и возвращаются в ответе (202), но в скачанном результате изображение сохраняет исходный размер.

**Problem:**
Проверено 2026-08-16 вживую (авторизованный запрос, план pro):

1. `POST /api/v1/convert` с `-F "file=@sample.svg" -F "to_format=png" -F "options[width]=400" -F "options[height]=240"`
   → 202, `completed`, скачанный PNG остаётся **200x120** (исходный размер)
2. `POST /api/v1/convert` с `-F "file=@ocr.jpg" (600x200) -F "to_format=png" -F "options[width]=300"`
   → 202, `completed`, результат по-прежнему **600x200** (исходный)
3. Валидация работает корректно: `-F "options[bogus]=1"` → `422 {"error":"Unsupported image option"}`

Трассировка: параметры валидируются в `app-symfony/src/Controller/Api/ConversionController.php`
(метод `validateImageOptions()`, ~строки 113–290, разрешены: `width`/`height`/`quality`/`background`),
но до фактического применения ресайза в воркере не доходят.

**Impact:**
Medium (feature broken):
- Пользователь не может изменить размер изображения через API, несмотря на интерфейс параметров
- Использование неправильное (options принимаются, но молча игнорируются — не то же, что 400 ошибка)
- Может привести к неудовлетворённости пользователя (выглядит как недоделка, а не известное ограничение)

**Recommendation:**
Проследить путь распространения `options` в цепочке:

1. `ConversionRequestDTO` — параметры принимаются, хранятся ли в DTO?
2. Сообщение в очередь (`conv.image` stream) — передаются ли options в сообщение? Какой формат?
3. Image-воркер (`app-workers/image`) — получает ли параметры и применяет их перед сохранением в S3?
4. Обратный путь к пользователю — изменения на диске должны быть отражены в результате

Либо реализовать полностью (конец-в-конец), либо явно задокументировать как не поддерживаемое и убрать валидацию из API.

**Acceptance Criteria:**
- Либо: `POST /api/v1/convert` с `options[width]=400` возвращает PNG ровно размером 400xN, сохранённый в S3 результатом воркера.
- Либо: Если ресайз не поддерживается, убрать валидацию из API (отклонять `options[width]` с 400 ошибкой).
- Протокол очереди между API и воркером документирует, передаются ли options в сообщении или нет.
- API tests или integration tests проверяют, что скачанное изображение имеет правильный размер.

**Decisions:**
- Карта в grooming, требует диагностики и уточнения цепочки обработки.
- Может быть связано с архитектурой WS-Gateway и тем, как воркер получает параметры сейчас.

**Контекст:** обнаружено в ходе проверки image conversion 2026-08-16.

**Status:** grooming
