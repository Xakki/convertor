### Админка /admin/workers: список хостов со сводкой + аккордеон воркеров

**Criticality:** High

**TAGS:**
- feature

**Description:**
Страница `/admin/workers` грузит сначала список ХОСТОВ со сводной статистикой; список воркеров выбранного хоста подгружается по кнопке (аккордеон).

**Problem:**
Текущий интерфейс не показывает агрегированный вид по хостам; нужна сводка с метриками перед детализацией воркеров.

**Impact:**
Без сводки по хостам администратор не может быстро оценить нагрузку и статус всей системы воркеров.

**Recommendation:**
**Бэкенд:**
- `POST /api/v1/internal/worker/liveness` принимает опциональное целое `inflight` (задач в работе у инстанса), пишется в существующую JSON-колонку `WorkerCapability.metrics` — без миграции.
- Новый `GET /api/v1/admin/workers/hosts` → `{ttlHours, hosts: [{host, workers, alive, disconnected, unknown, stale, lastSeen, inflight, inflightKnown, cpu{avg,max}, mem{avg,max}, load{avg,max}, images[], versions[], hasAi, hasSeed}]}`. Хост `null` (легаси-строки) — отдельная корзина, сортируется последней.
- `GET /api/v1/admin/workers` получает два взаимоисключающих опциональных фильтра: `?host=<name>` (реальный хост, включая хост, буквально названный `__none__` — это просто имя) и `?hostNull=1` (легаси-корзина `host IS NULL`); оба вместе → 400. Без параметров форма ответа не меняется (аддитивно). Ревью CNV-61 сняло прежний сентинел `?host=__none__` — коллизионноопасный на клиенте (реальный хост с тем же именем и null-корзина мапились бы на один Alpine `:key`).
- Агрегация — в PHP внутри `WorkerStatsProvider` поверх готового `toRow()`, НЕ через GROUP BY: `status` приходит от реконсилятора, `stale` выводится от `ttlHours` — дублировать вывод в SQL значит развести две витрины.

**Воркеры/gateway:**
- gateway отдаёт `len(credits.inflight)` в существующем liveness-пуше (`workers/gateway/ws_server.py` → `liveness.py::_Instance.to_payload()`). Новых эндпоинтов и транспортов не добавляем. Пересборка нужна только gateway, воркеры не трогаем.

**Фронт:**
- `app-symfony/templates/admin/workers.html.twig` — двухуровневый аккордеон (хост → воркеры → детали воркера), ленивая загрузка воркеров хоста по кнопке. Поллинг 15с обязан мержить хосты по ключу НА МЕСТЕ, иначе переприсваивание массива схлопывает открытые хосты. Один `<tbody>` на хост (вложенный `<tbody>` — невалидный HTML).

**Acceptance Criteria:**
- сводка по хостам грузится первой, воркеры — только по кнопке;
- открытый аккордеон переживает автообновление раз в 15с;
- корзина «без хоста» видна и кликабельна;
- `inflightKnown=false` рисуется как «—», а не как 0;
- `make phpstan` / `make cs-check` / `make test` зелёные.

**Decisions:** *(resolved grooming questions — keep on the card after `todo/` so the rationale survives)*
- «задач в работе» в сводке по хосту — нужна (поэтому и появился `inflight` в liveness) — подтверждено с @user
- проверка в браузере — под user 1

## Execution Log

**Реализовано:** gateway отдаёт `inflight` в liveness-пуше (сброс в «неизвестно» при дисконнекте), бэкенд принимает и пишет в существующую JSON-колонку `metrics` без миграции, добавлены `GET /api/v1/admin/workers/hosts` и фильтры `?host=` / `?hostNull=1`, фронт — двухуровневый аккордеон с ленивой подгрузкой и мержем на месте. 

**Ревью:** нашло и починило: фоновое обновление размонтировало таблицу (гейт по `host.loading`/`host.error` вместо `host.loaded`), коллизия сентинела `__none__` (заменён на отдельный параметр `?hostNull=1`), перетирание `metrics` при частичном пуше (стал read-modify-write). Отдельно исправлена шкала: `cpu`/`mem`/`load` — доли 0..1 на всём пути (`workers/common/ws_client.py:206-212`), фронт ошибочно считал их процентами, плюс агрегат округлялся до 1 знака и терял точность. 

**QA:** phpstan/cs чисто, юнит 346, полный прогон — только 2 предсуществующих падения `ConversionTextInputControllerTest` (PHPUnit 13 не мокает enum `BillingMode`).
