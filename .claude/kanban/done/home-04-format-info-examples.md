### Блок «форматы + лимиты» и реальные примеры результатов из S3

**Criticality:** High

**TAGS:**
- feature
- frontend
- backend

**Description:**
Часть эпика [[home-00-epic]]. Выполняется после [[home-03-conversion-
variants]], перед [[home-05-file-viewers]] (превьюшки примеров используют
те же вьюеры, что делает [[home-05-file-viewers]] — координировать формат
разметки/data-атрибутов результата, чтобы не переделывать).

Два независимых, но соседних куска:
1. **Блок «форматы + лимиты»** — статичная информационная секция: матрица
   поддерживаемых форматов (детальнее, чем витрина [[home-03-conversion-
   variants]]) + таблица лимитов/тарифов. Источник копирайта —
   ROADMAP.md «Справочные данные» → «Матрица поддерживаемых конвертаций» +
   «Лимиты и тарифы» (канонический источник, ⚠️ числа лимитов там помечены
   как «предложение, финализируется в `plan-quota-daily-monthly`» — при
   расхождении на момент реализации сверяться с актуальной картой/кодом
   `QuotaService`, не копировать слепо).
2. **Реальные примеры конвертаций из S3** — по решению D3 (см.
   [[home-00-epic]]) примеры генерируются ОДИН РАЗ заранее консольной
   командой и складываются в S3, страница их просто показывает.

**Problem:**
Нет ни явной информации о лимитах/форматах (кроме витрины из
[[home-03-conversion-variants]], которая не показывает лимиты и не даёт
живых примеров результата), ни доказательства качества конвертации
(«как выглядит результат») — пользователь не видит, что получит, до
того как сам загрузит файл.

**Impact:**
Отсутствие доверия/наглядности снижает конверсию посетителей в
пользователей; лимиты, важные для выбора плана, нигде не показаны на
лендинге.

**Recommendation:**

**Часть A — информационный блок:**
- Twig-партиал/секция на `conversion/index.html.twig` с таблицей форматов
  (категория → source → target → движок опционально) и таблицей
  лимитов/тарифов (4 тира × free/basic/pro, см. ROADMAP.md таблицу цен).
  Статичный контент (не через API — сами лимиты не эндпоинт, `GET
  /api/v1/quota` отдаёт лимиты ТЕКУЩЕГО юзера, не публичную тарифную сетку).
  Тексты — через i18n-ключи (см. [[home-07-i18n]]).

**Часть B — примеры из S3 (нужен новый бэкенд-компонент):**
- Symfony console-команда (например `app:examples:seed`, класс
  `App\Command\SeedExamplesCommand` под `#[AsCommand]`) + `make`-таргет
  (например `make seed-examples`), прогоняющая курируемый небольшой набор
  реальных конвертаций через СУЩЕСТВУЮЩИЙ пайплайн (тот же
  `App\Service\Conversion\*` / Messenger-флоу, что и обычная конвертация —
  НЕ отдельная логика) и пишущая результаты в стабильный S3-префикс
  результатов (например `examples/<category>/<slug>.<ext>` в бакете
  `${S3_BUCKET_PREFIX}-results`).
- Набор — по ОДНОЙ показательной паре source→target на категорию из
  ROADMAP.md «Справочные данные» (документы, PDF-операции, разметка,
  данные, изображения, OCR, аудио, видео, видео→аудио; STT/TTS — опционально,
  если не тянет лишних внешних зависимостей на момент реализации). Исходные
  файлы для примеров — небольшие, лицензионно чистые (например
  CC0/собственного авторства) сэмплы, добавить в репозиторий или
  сгенерировать программно (не тянуть посторонние копирайтные файлы).
- Frontend читает список примеров и отдаёт на страницу через presign
  (`mcp__minio__presign_download` при построении/на бэке через существующий
  `S3Storage`-сервис — уточнить у `backend-architecture`, как сейчас
  presign'ится `download`/`source` в `ConversionController`, переиспользовать
  тот же паттерн) либо anonymous-get, если бакет/префикс настроен на
  публичное чтение только для `examples/` (см. решение по видимости ниже).
- Все S3-операции по правилам проекта — ТОЛЬКО через MCP `minio`
  (`mcp__minio__*`), не `mc`/`mc admin` вручную.
- Прочитать skill `backend-architecture` (как встроить seed-команду в
  существующий Registry/Manager-флоу, не городить параллельную логику),
  skill `api-design` (если понадобится новый публичный эндпоинт
  «список примеров» — версионировать под `/api/v1/`, JSON, документировать
  через NelmioApiDocBundle), ROADMAP.md «Справочные данные».

**Acceptance Criteria:**
- Информационный блок с матрицей форматов и таблицей лимитов виден на `/`,
  текст — через i18n-ключи, данные сверены с ROADMAP.md на момент
  реализации.
- `make seed-examples` (или аналог) успешно прогоняет курируемый набор
  через реальный пайплайн конвертации и кладёт результаты в
  `examples/<category>/…` бакета `${S3_BUCKET_PREFIX}-results`.
- Хотя бы по одному примеру source→target на каждую MVP-категорию из
  ROADMAP-таблицы (Стадия 1) виден на странице со ссылкой на скачивание/
  просмотр результата.
- Ссылки на примеры — presigned либо anonymous-get по решению видимости
  (см. Decisions), не требуют логина для просмотра.
- S3-операции по подготовке/проверке бакета выполнены через MCP `minio`,
  не вручную через `mc`.
- Tests/QA green: `make test`, `make phpstan`, `make cs-check`.

**Decisions:**
- D3 (см. [[home-00-epic]]): примеры — реальные, сгенерированы один раз
  заранее консольной командой через реальный пайплайн, хранятся в S3,
  курируемый набор ~1 пара на категорию.
- Видимость `examples/`-префикса в S3 (presigned на каждый рендер страницы
  vs `bucket_anonymous_get` только для этого префикса) — решается
  исполнителем на этапе реализации по факту того, насколько просто
  ограничить anonymous-политику ИМЕННО префиксом `examples/` в MinIO;
  presigned-URL на бэке — безопасный дефолт, если точечная anonymous-
  политика на префикс окажется неудобной через доступные MCP-инструменты
  (ограничение MCP: кастомные IAM-политики недоступны — только встроенные
  `readwrite`/`readonly`/… через `policy_attach`, см. правило проекта S3 /
  MinIO).
- Лимиты/тарифы на странице — статичный текст по ROADMAP.md на момент
  реализации, не отдельный публичный API (существующий `/api/v1/quota`
  отдаёт лимиты только текущего юзера, не тарифную сетку).
