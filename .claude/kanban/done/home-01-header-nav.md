### Хедер и навигация: «Войти» на /login, докс/админ/бот-ссылки

**Criticality:** High

**TAGS:**
- feature
- frontend

**Description:**
Часть эпика [[home-00-epic]]. Выполняется ПОСЛЕ [[home-07-i18n]] (заводит
текст сразу через ключи перевода, включая переключатель языка — координировать
размещение переключателя с этой подзадачей, не дублировать компонент).

Сейчас `templates/base.html.twig` — минимальный Symfony-скелет без
header/footer-блоков; `conversion/index.html.twig` не рендерит никакой шапки/
навигации. Единственный вход — кнопка Telegram прямо в форме. Визуальный
референс (мок, НЕ раздаётся сервисом) — `app-front/components/header.html`
(sticky nav с quota-бейджем и ссылкой на админку).

**Problem:**
Нет единой точки входа/навигации на странице: нет ссылки на логин, докс,
админку (для админов), бота. Кнопка Telegram в форме конвертации — это старый
подход, который должен смениться на переход в `/login`, где уже реализован
полный набор провайдеров.

**Impact:**
Пользователь не может быстро понять, где логин/докс/бот; юзабилити лендинга
страдает без единой навигации.

**Recommendation:**
- Добавить в `templates/base.html.twig` (или как `{% include %}`-партиал
  `templates/components/header.html.twig`) шапку сайта: логотип/название,
  переключатель языка (см. [[home-07-i18n]]), ссылка «Войти» → `/login`,
  ссылка «Docs» → `/api/doc` (Swagger UI, роут уже существует —
  `app-symfony/config/routes/nelmio_api_doc.yaml`), ссылка «Bot» →
  `https://t.me/{{ telegram_bot_username }}` (env `TELEGRAM_BOT_USERNAME`,
  сейчас `anyconvertor_bot` — прокинуть как параметр Twig-глобал через
  `config/services.yaml` `parameters:`, не хардкодить в шаблоне), ссылка
  «Admin» → `/admin` (`admin_dashboard` роут,
  `App\Controller\Admin\AdminController`) — ПОКАЗЫВАТЬ ТОЛЬКО для
  `is_granted('ROLE_ADMIN')`.
- Убрать текущую отдельную кнопку Telegram-логина из формы конвертации на
  `conversion/index.html.twig` — вход теперь только через «Войти» → `/login`.
  Убедиться, что анонимный guest-cookie флоу конвертации НЕ завязан на эту
  кнопку и продолжает работать без логина (для форматов вне ai/video).
- **ВАЖНО (регрессия):** в `converterApp().submit()` есть отдельный путь для
  ai/video-гейта — при `403` + `isAuthRequired(res)` сейчас вызывается
  `this.startLogin()` (см. `conversion/index.html.twig:587-591`), который
  сегодня открывает ИМЕННО инлайн Telegram-флоу. При удалении
  `startLogin()`/инлайн-кнопки этот обработчик должен вести пользователя на
  `/login` (редирект или показ приглашения со ссылкой), а НЕ оставаться
  битой ссылкой на удалённую функцию — иначе гейт ai/video для гостя
  молча ломается.
- Если пользователь уже залогинен — показать в шапке имя/аватар + ссылку на
  логаут вместо «Войти» (проверить существующий `security.yaml`/сессию,
  как определяется текущий юзер в Twig — `app.user`).
- Стек: Twig + Alpine.js (для мобильного бургер-меню, если нужен) + Tailwind
  CDN, без npm/build (см. правило проекта Frontend Rules).

**Acceptance Criteria:**
- Шапка видна на `/` (и в идеале переиспользуется на `/login` — проверить,
  не сломает ли это существующую вёрстку `auth/login.html.twig`).
- «Войти» ведёт на `/login`, без popup.
- «Docs» ведёт на `/api/doc` и открывает Swagger UI.
- «Admin»-ссылка видна только `ROLE_ADMIN`, для остальных — отсутствует
  (не просто скрыта через CSS).
- «Bot»-ссылка — валидный `t.me/<username>` deep-link.
- Анонимная конвертация (guest-cookie, форматы вне ai/video) продолжает
  работать без регрессий после удаления инлайн-кнопки Telegram.
- Гейт ai/video для гостя (`403` + `auth_required` от `POST /api/v1/convert`)
  после удаления инлайн-`startLogin()` ведёт пользователя на `/login`
  (не битая ссылка на удалённую функцию, не молчаливый провал).
- Tests/QA green: `make test`, `make phpstan`, `make cs-check`.

**Decisions:**
- D1 (см. [[home-00-epic]]): «Войти» → существующая `/login`, auth не
  переделываем, без popup.
- Ссылки хедера (докс/админ/бот) — как описано выше, согласовано в
  [[home-00-epic]].
- Читать skill `redesign-auth-access-contract` перед изменением
  логин-точек входа и гейтинга гостя — контракт guest-cookie/ROLE_GUEST не
  меняется этой подзадачей.
- Соседняя открытая карточка `todo/user-dashboard-page.md` строит
  `/dashboard` (история/квоты/аккаунт) — эта подзадача НЕ дублирует ту
  функциональность в хедере; когда `/dashboard` появится, её тимлид
  переиспользует хедер/nav, сделанные здесь (см. [[home-00-epic]]
  «Что уже готово»).
