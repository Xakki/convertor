### Параметризовать i18n таймаута claim воркера

**Criticality:** Medium

**TAGS:**
- tech-debt

**Description:**
Текст `poll_gave_up_message` в ru/en обещает ожидание «до часа», хотя фактическое
окно задаёт `WORKER_CLAIM_TIMEOUT_MINUTES` и может быть изменено через env.

**Problem:**
При изменении env копирайт молча расходится с поведением gateway и PHP.

**Impact:**
Пользователь получает неверное ожидание времени обработки, а сопровождение должно
помнить о ручной синхронизации строк перевода с конфигурацией.

**Recommendation:**
Передавать фактическое значение как параметр Symfony translation для
`poll_gave_up_message` в ru/en. Не менять контракт worker и не дублировать
конфигурацию в UI.

**Acceptance Criteria:**
- Сообщения ru/en используют trans-параметр, полученный из
  `WORKER_CLAIM_TIMEOUT_MINUTES`.
- При изменении env текст показывает актуальное число минут; дефолт 60 сохраняется.
- Есть покрытие передачи параметра и обеих локалей.
- Тесты/QA green: pytest; make test; make build.

**Decisions:**
- 2026-08-14: параметризовать перевод, а не оставлять ручной комментарий;
  решение выделено из п.1 CNV-73.
