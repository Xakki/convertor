### Админка: кнопка удаления отключённых воркеров из БД

**Criticality:** High

**TAGS:**
- feature

**Description:**
На странице `/admin/workers` — добавить одну общую кнопку «Удалить отключённых», которая массово чистит строки таблицы `worker_capabilities` со статусом `disconnected` или `unknown` (кроме seed-строк).

**Problem:**
Отключённые и неизвестные воркеры (например, после сбоя, переподключения или изменения конфигурации) накапливаются в БД. Нужен удобный способ их массового удаления через UI администратора без необходимости прямых запросов к БД.

**Impact:**
Без инструмента администратор не может эффективно очищать таблицу `worker_capabilities` от мертвых записей; данные накапливаются и усложняют анализ актуального статуса воркеров.

**Recommendation:**

**Решения пользователя (2026-08-04):**
- Удаляем строки со статусом `disconnected` ИЛИ `unknown`, любого возраста
- **Seed-строки (`instance_id='__seed__'`) исключены обязательно** — они как раз `unknown`, без исключения кнопка снесла бы каноническую матрицу форматов
- Кнопка только одна, общая, рядом с «Обновить»; поштучного удаления строки воркера не делаем

**Реализация:**
- `DELETE /api/v1/admin/workers/stale` → `{"deleted": N}`
- Метод репозитория с предикатом `status IN ('disconnected', 'unknown') AND instance_id != '__seed__'`
- Подтверждение в UI перед вызовом

**Acceptance Criteria:**
- Seed-строки (`instance_id='__seed__'`) переживают нажатие кнопки (обязателен тест)
- Alive-строки не удаляются
- Пустой результат → `{"deleted": 0}` и HTTP 200
- Доступ только админам (не-админ → 403)
- Нажатие не ломает аккордеон и поллинг на странице
- `make phpstan` без ошибок
- `make cs-check` без ошибок
- Тесты зелёные

**Decisions:**
- **Что уже есть и НЕ дублируется:** авто-GC `WorkerCapabilityGcService::run()` (`src/Schedule.php:40`, раз в час) удаляет по возрасту `lastSeen` старше `WORKER_CAPABILITY_GC_TTL_HOURS` (168 ч), без учёта статуса, кроме `__seed__`. Новая кнопка чистит по СТАТУСУ — это другая операция, поведение авто-GC не трогаем. Ручной make-таргет с настраиваемым TTL — отдельная карточка CNV-67 в `todo/`
- **Гонка с живым воркером:** liveness-пуш умеет только UPDATE, вставок нет, поэтому удалённая строка не воскресает от пинга. Восстановление — через команду перерегистрации от gateway: ~30 с, но до 5 мин при активном кулдауне 300 с (`workers/gateway/config.py:145`). Текст подтверждения должен это отражать

## Execution Log

**Реализовано:** `DELETE /api/v1/admin/workers/stale` → `{"deleted": N}`, предикат `status IN ('disconnected','unknown') AND instance_id != '__seed__'` (константа seed переиспользована из репозитория), после удаления сбрасывается кэш матрицы форматов. 

**UI:** кнопка «Удалить отключённых» рядом с «Обновить», с подтверждением, состояние изолировано от поллинга. 

**Тесты:** seed-строки переживают нажатие, `alive` переживают, пустой случай → 0, не-админ → 403.
