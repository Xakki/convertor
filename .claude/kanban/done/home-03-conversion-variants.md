### Витрина вариантов конвертации (категории/пары форматов)

**Criticality:** Medium

**TAGS:**
- feature
- frontend

**Description:**
Часть эпика [[home-00-epic]]. Выполняется после [[home-02-text-input]] в
цепочке зависимостей эпика, перед [[home-04-format-info-examples]].

Сейчас на `conversion/index.html.twig` нет визуального обзора того, что
вообще умеет конвертировать сервис — только `<select>` целевого формата,
который заполняется динамически после того, как пользователь уже загрузил
файл. Новый пользователь не видит матрицу возможностей ДО загрузки файла.

Источник данных — уже существующий публичный `GET /api/v1/formats`
(`App\Service\Conversion\ConversionRegistry`), отдающий
`[{from, to, category, isAi, ocrCapable}]`. Никакого нового бэкенда для
самих данных не требуется.

**Problem:**
Лендинг не продаёт возможности сервиса: пользователь должен сначала
загрузить файл, чтобы узнать, какие форматы вообще поддерживаются.

**Impact:**
Высокий bounce на лендинге — непонятно, что делает сервис, до совершения
действия (загрузки файла).

**Recommendation:**
- Добавить на `conversion/index.html.twig` (или отдельный Twig-партиал
  `templates/components/format-variants.html.twig`, инклюдится с главной)
  блок-витрину: карточки/сетка по категориям (документы, изображения,
  аудио, видео, данные, разметка, OCR, AI STT/TTS — см. ROADMAP.md
  «Справочные данные» → таблица категорий) с несколькими показательными
  парами source→target на каждую категорию.
- Данные — из `GET /api/v1/formats`, агрегировать на клиенте (Alpine.js)
  по полю `category`; `isAi` — визуально отметить бейджем (AI-тир, платно/
  вход обязателен — см. гейтинг в skill `redesign-auth-access-contract`).
- Клик по паре/категории в витрине — UX-шорткат: скроллит/фокусирует
  форму конвертации и, если возможно без лишних сложностей, прешевает
  режим (файл или текст — см. [[home-02-text-input]]) с
  предвыбранным целевым форматом. Не обязательно жёстко реализовывать
  предзаполнение целевого формата в MVP этой подзадачи, если добавляет
  существенную сложность — тогда просто скролл-якорь к форме.
- Никаких новых бэкенд-эндпоинтов — только фронтенд поверх
  `GET /api/v1/formats`.
- Прочитать skill `api-design` (контракт `/api/v1/formats`, ответ уже
  стабилен, не менять) и `backend-architecture` (структура
  `ConversionRegistry`, откуда берутся категории/AI-флаг) и ROADMAP.md
  «Справочные данные» → «Матрица поддерживаемых конвертаций» (канонический
  источник списка категорий/форматов для копирайта витрины).

**Acceptance Criteria:**
- Блок-витрина видим на `/` ДО загрузки файла, построен по данным
  `GET /api/v1/formats` (не хардкод списка форматов в Twig/JS).
- Категории и AI-бейдж соответствуют полям `category`/`isAi` из ответа
  API.
- Витрина адаптивна (мобильный/десктоп), использует только Tailwind CDN +
  Alpine.js (без npm/build).
- Клик по элементу витрины визуально ведёт пользователя к форме
  конвертации (минимум — скролл-якорь).
- Tests/QA green: `make test`, `make phpstan`, `make cs-check`.

**Decisions:**
- Данные — только `GET /api/v1/formats`, никакого нового бэкенда (см.
  [[home-00-epic]] Facts).
- Предзаполнение формы по клику — best-effort, не блокирует приёмку, если
  усложняет реализацию непропорционально ценности.
