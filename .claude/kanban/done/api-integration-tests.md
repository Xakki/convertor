### Интеграционные тесты API + замер скорости конвертаций

**Критичность:** High

**TAGS:**
- feature
- tech-debt

**Описание:**
Стадия 1. Интеграционных тестов API нет: реальный end-to-end прогон конвертаций через эндпоинты и замер скорости отсутствуют. Покрыты только нижние слои/моки.

**Проблема:**
- Нет тестов, которые гоняют реальные файлы через эндпоинты (submit → status → download).
- Нет замеров скорости конвертаций — непонятно, какие типы быстрые/медленные и где регресс.

**Влияние:**
Регрессии в API и воркерах ловятся только вручную; нет базовых таймингов для перформанс-бюджета.

**Решение:**
- Интеграционные тесты для ВСЕХ реализованных эндпоинтов с реальным end-to-end прогоном файлов: submit `POST /api/v1/convert` → poll `GET /convert/{id}/status` → `GET /convert/{id}/download`.
- По одному кейсу на категорию конвертации (image / data / ffmpeg / document / ...).
- **Замер скорости** каждой конвертации — фиксировать тайминги по типам.
- Помечать маркером `integration` (требует поднятого стека: KeyDB Streams + S3 + воркеры).
- Запуск через make-таргет.

**Критерии приёмки:**
- Каждый реализованный эндпоинт прогнан на реальном файле end-to-end.
- Тайминги конвертаций по типам зафиксированы.
- Запускается через make-таргет.

**Зависимости:**
- Зависит от рабочих воркеров (Стадия 1) — связать [[finish-worker-compose-wiring]], [[smoke-run-verify]].

**Decisions:**
- Выявлено при аудите 2026-06-20: интеграционного покрытия API нет.
