### Гостевая история под формой + явное согласие на куки

**Criticality:** Medium

**TAGS:**
- feature
- frontend

**Description:**
Бэкенд гостевую историю уже поддерживает: `GET /api/v1/convert/history`
работает для `ROLE_GUEST` (cookie `guest_id`), для гостя без материализации →
`{"items":[]}`. Фронт (`_converter_app_script.html.twig` `init()`) зовёт
`loadHistory()` ТОЛЬКО внутри `tryRefresh().then(ok => if(ok) loadHistory())`
— а `tryRefresh()` требует JWT-refresh-cookie, которого у гостя нет → на свежей
загрузке/F5 гостю история не грузится (внутри сессии после своей конвертации —
грузится). Секция истории уже структурно «под формой».

Пользователь хочет: показывать гостю его список конвертаций под формой, но
ТОЛЬКО если он согласился на куки. Сейчас cookie-баннер (home-06)
информационный (только «Понятно»), явного согласия нет.

**Acceptance Criteria:**
- Cookie-баннер становится явным выбором: «Принять» / «Отклонить» (было —
  информационный). Сохраняем результат в cookie `cookie_consent`
  (`accepted`/`declined`), SameSite=Lax.
- Гостевая история под формой показывается ТОЛЬКО когда `cookie_consent=accepted`
  (у гостя). Для залогиненного — как раньше (история грузится по JWT).
- `loadHistory()` вызывается на `init()` для гостя, если согласие принято
  (не только после `tryRefresh`). Плечо `authFetch` уже шлёт guest-cookie.
- Гостевая секция помечена как «на этом устройстве» (история cookie-scoped,
  эфемерна) — отдельная формулировка от залогиненной, i18n EN+RU.
- Обновить текст privacy/cookie (home-06) под модель accept/decline.
- Гостевой guest_id — строго необходимая кука, ставится всегда (не зависит от
  согласия); согласие гейтит ТОЛЬКО показ истории, а не саму конвертацию.
- `make phpstan`/`cs-check`/`test` зелёные; проверить оба пути (accepted →
  история видна; declined → скрыта).

**Decisions:**
- Пользователь выбрал «явный Принять/Отклонить» — меняет решение home-06
  (баннер был информационным, т.к. все куки строго необходимы). Теперь баннер
  = выбор, и показ истории гейтится согласием.
- Соседняя карточка `todo/user-dashboard-page.md` строит отдельный `/dashboard`
  — тут только минимальная гостевая история на главной, не дублировать дашборд.
