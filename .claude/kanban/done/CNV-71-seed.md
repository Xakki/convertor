### Каталог форматов независимо от воркеров + удаление __seed__

**Criticality:** High

**TAGS:**
- tech-debt

**Description:**
На сайте по умолчанию доступны ВСЕ форматы конвертации независимо от того, какие воркеры сейчас подключены; наличие воркера проверяется в момент создания конвертации. Seed-строки `__seed__` удаляются.

**Problem:**
Сегодня каталог форматов на сайте (`/formats`, SEO-страницы, валидация пар) на 100% зависит от строк в `worker_capabilities` (`ConversionRegistry::buildRoutingPairs()`, `ConversionRegistry.php:432-458`), а единственная гарантия непустого каталога — seed-строки `instance_id='__seed__'` со спец-обработкой в 6 местах кода.

**Impact:**
Без независимого от воркеров каталога сайт показывает пользователю только те форматы, для которых прямо сейчас есть хоть одна (пусть и мёртвая) строка воркера в БД, а seed-строки навсегда остаются костылём и источником особых случаев в GC/админке/регистрации.

**Recommendation:**
Сгенерировать статичный каталог форматов из кода воркеров (CNV-71-01), перевести на него `/formats`/SEO/валидацию (CNV-71-02), проверять доступность конкретного воркера только в момент создания конвертации по гибридной схеме (CNV-71-03), и только после этого убрать seed-строки и их спец-обработку (CNV-71-04).

**Решения пользователя (2026-08-04):**
1. Источник «всех форматов» — **генерируется из матриц Python-воркеров** один раз на сборке и коммитится в репо. Источник правды остаётся в коде воркеров, ручной дубль исчезает.
2. При отсутствии воркера — **гибрид**: если строка воркера нужного типа в БД есть (пусть и offline) — задача принимается и ждёт с таймаутом; если такого типа не было никогда — сразу отказ с понятным текстом.
3. Критерий «воркер есть» — **наличие строки в `worker_capabilities`**, не статус alive (устойчиво к рестартам и деплоям).
4. Форматы без живого воркера в UI показываются **как обычные**, без пометки недоступности.

**Факты разведки (проверены по коду 2026-08-04, не переспрашивать):**
- `ConversionRegistry::buildRoutingPairs()` (`app-symfony/src/Service/Conversion/ConversionRegistry.php:432-458`) строит матрицу на 100% из `WorkerCapabilityRepository::findAllCapabilities()`; статического фолбэка нет. Статус alive/disconnected сознательно НЕ читается (:477-486) — формат пропадает только при удалении строки. Кэш `cache.app`, ключ `conv.worker.matrix`, TTL 3600с (:398-413), инвалидация из `invalidateMatrix()` (:312-316).
- Потребители: `GET /api/v1/formats` (`ConversionController.php:669,685-690`); `ConversionManager::createConversion()` (:66-121) — при неподдерживаемой паре и неудачном chain-BFS `findPath()` → 400 (текстовый вход 422); SEO-страница `/convert/{src}-to-{dst}` (`ConversionPageController.php:32-51`) → 404. Sitemap-генератора в проекте нет.
- Каталог сегодня продублирован вручную в 3 местах: `ROADMAP.md:182-207`, `CuratedConversionPairs.php:22-33`, и 5 захардкоженных матриц воркеров (`workers/image/worker.py:67`, `workers/libreoffice/worker.py:135`, `workers/ffmpeg/worker.py:63`, `workers/data/worker.py:20`, `workers/ai/worker.py:43-55`), которые попадают в БД через `POST /api/v1/worker/register`.
- Живых пар сейчас 394 (document 154, image 78, audio 67, video 67, data 28; 25 через AI).
- **Незаклеймленная запись висит в стриме вечно**: app-level TTL и дедлеттера для задач, которые никто не взял, НЕТ. Reclaim (`workers/gateway/reclaim.py:29-50`, пороги `config.py:95-100`) работает только по уже заклеймленным записям исчезнувшего консьюмера. Значит ветка «ждать воркера» требует НОВОЙ механики протухания.
- Seed-строки участвуют в матрице как статический снапшот и сегодня являются единственной гарантией «матрица не опустеет» (комментарий в `WorkerCapabilityGcService.php:56-75`). Спец-обработка `__seed__` в 6 местах: участие в матрице; исключение из GC (`WorkerCapabilityGcService.php:52`); исключение из `markSilentDisconnected()` (`WorkerCapabilityRepository.php:268-289`); исключение из admin bulk-delete `deleteStaleByStatus()` (:317-335); бейдж в админке (`WorkerStatsProvider.php:51,108,252,362`); блокировка регистрации под этим instanceId (`WorkerController.php:50,68-96`).

**Порядок обязателен:** каталог должен появиться и стать источником для `/formats`/SEO/валидации ДО удаления seed-строк, иначе при пустой БД сайт останется с пустым списком форматов и 400 на любую конвертацию.

**Открытый вопрос для реализации (решить при старте подзадачи 03):** конкретное значение таймаута ожидания воркера и что происходит по его истечении (пометить конвертацию failed с отдельной причиной? уведомить пользователя?). Предложение по умолчанию — таймаут в env, дефолт 15 минут, по истечении конвертация переходит в failed с отдельным кодом причины. Подтвердить у пользователя перед реализацией.
