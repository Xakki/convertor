### Backlog: доп. провайдеры авторизации (Google / GitHub OAuth, deferred)

**Критичность:** Low

**STATUS:** done — реализовано эпиком oauth-00 (мультипровайдерный OAuth).

**TAGS:**
- feature
- deferred

**Описание:**
В разделе «Аутентификация» `ROADMAP.md` (подраздел «Другие надёжные сервисы») заявлены доп. провайдеры входа сверх основного метода. Текущая авторизация = Telegram Login Widget + SMS OTP (резерв) — реализовано. Эти OAuth-провайдеры запланированы, но не запланированы по срокам; фиксируем, чтобы не потерять.

**Проблема / scope:**
- **Google OAuth** — вход через Google-аккаунт (раздел «Аутентификация» в `ROADMAP.md`).
- **GitHub OAuth** — вход через GitHub-аккаунт (раздел «Аутентификация» в `ROADMAP.md`).

**Влияние:**
Без доп. провайдеров охват входа ограничен Telegram + SMS; часть пользователей без Telegram-аккаунта остаётся без удобного метода входа.

**Решение:**
Держать как замороженный бэклог. При разморозке — реализовать через общий OAuth-абстрактный слой Symfony Security (по образцу существующей auth-логики).

**Критерии приёмки:**
- (при разморозке) Каждый провайдер завершает тестовый OAuth-флоу и создаёт/находит User.

**Open questions:**
- MVP или post-MVP? Решить при груминге — нужны ли Google/GitHub OAuth к запуску или после.

**Decisions:**
- Заведено 2026-06-20 по просьбе пользователя — записать отложенные провайдеры авторизации, чтобы не потерять.
