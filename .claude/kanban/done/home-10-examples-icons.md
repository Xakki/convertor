### Живые примеры — кликабельные иконки файлов (исходный + результат)

**Criticality:** Medium

**TAGS:**
- feature
- frontend
- backend

**Description:**
Сейчас карточка примера (`partials/_converter_examples.html.twig`) показывает
бейджи + ТРИ текстовых контрола (Просмотр / Скачать / превью по типу). Нужно
заменить на ДВЕ кликабельные иконки файлов — исходного и итогового формата —
без отдельных кнопок просмотр/скачать.

`GET /api/v1/examples` сейчас отдаёт только результат (`url` →
`/api/v1/examples/file/{category}/{name}`), исходные sample-файлы
(`app-symfony/resources/seed-examples/`) публично не отдаются.

**Acceptance Criteria:**
- Карточка примера: две иконки — исходного формата и итогового; обе кликабельны.
  Клик = превью (image/pdf/audio/video/text — через существующие
  `openViewer`/`togglePlayer`/`openPreviewFromUrl`) ЛИБО скачивание для
  непревьюабельных. Отдельных кнопок «Просмотр»/«Скачать» больше нет.
- Бэкенд публично отдаёт исходные sample-файлы (расширить `ExampleController`:
  новый inline-стрим-эндпоинт для source + добавить в `GET /api/v1/examples`
  поля `source_url`, `source_mime`, исходный формат). Whitelist, без
  path-traversal (как у результата).
- Набор иконок — inline-SVG map по типу файла/категории (без нового CDN, по
  правилам фронта), с дефолтной иконкой для неизвестных.
- XSS-safe как в home-05 (иконки — статичные SVG, никакого `innerHTML`
  байтов результата).
- `make phpstan`/`cs-check`/`test` зелёные; примеры рендерятся, клики работают.

**Decisions:**
- Пользователь выбрал «обе иконки, обе кликабельны» → нужен публичный отдатчик
  исходных файлов.
- Тот же трёхуровневый набор методов (`openViewer`/`togglePlayer`/
  `openPreviewFromUrl`/download) используется и в истории пользователя — при
  редизайне карточки примера НЕ ломать историю (другой call-site, не трогать
  без нужды).
