### Управление примерами конвертаций из админки (пометить существующую)

**Criticality:** Medium

**TAGS:**
- feature
- backend
- frontend
- admin

**Description:**
Сейчас «живые примеры» на лендинге — **захардкоженный** список в
`App\Service\Examples\ExampleCatalog` (пары source→target + sample-файлы в
`app-symfony/resources/seed-examples/`), которые `make seed-examples`
(`App\Command\SeedExamplesCommand`) прогоняет через реальный пайплайн и кладёт
результат в стабильный S3-префикс `examples/<category>/…`. Отдаёт их
`App\Controller\Api\ExampleController` (`GET /api/v1/examples` +
`/file/...` + `/source/...`, публично).

Пользователь хочет, чтобы **админ сам указывал, какие конвертации использовать
как примеры**, из админки (`/admin`, `App\Controller\Admin`). Выбранный подход
(решение пользователя): **пометить СУЩЕСТВУЮЩУЮ конвертацию как пример** (не
загрузка с нуля).

**Acceptance Criteria:**
- Новая сущность `Example` (+ миграция): ссылка на конвертацию/файлы, категория,
  from/to, стабильные S3-ключи результата и исходника (в `examples/`-префиксе),
  порядок/флаг видимости, timestamps.
- В админке: список конвертаций (или список примеров) с действием «Сделать
  примером» / «Убрать из примеров». При пометке: input+output существующей
  конвертации КОПИРУЮТСЯ в стабильный `examples/`-префикс (как это делает
  `SeedExamplesCommand` через `S3Storage::copyObject`), создаётся запись
  `Example` (untracked-копия, чтобы 24ч-очистка её не сметала).
- `ExampleController` отдаёт примеры из БД (`Example`), а не из хардкода
  `ExampleCatalog`. Публичный контракт `GET /api/v1/examples` (поля
  `category/from/to/filename/mime/size/previewable/url/source_url/source_mime/
  source_format`) — СОХРАНИТЬ (фронт home-04/home-10 не менять).
- Курируемый небольшой набор (по одной показательной паре на категорию) — как
  сейчас; админ может заменить/добавить.
- Совместимость: `make seed-examples` либо остаётся как первичный сидер
  (создаёт `Example`-записи вместо хардкода), либо помечается deprecated —
  решить при реализации.
- `make phpstan`/`cs-check`/`test` зелёные; примеры на лендинге работают из
  БД-модели; клик-превью (fix токена) не сломан.

**Decisions:**
- Подход A («пометить существующую конвертацию») — выбран пользователем
  (2026-07-21). Вариант «создать с нуля через загрузку в админке» — отклонён на
  этот заход.
- Все S3-операции в коде — через app-S3-клиент (`S3Storage`), как в
  `SeedExamplesCommand`; НЕ `mc`. Примеры-объекты — untracked (нет `FileStorage`
  строки), чтобы `FileCleanupService` их не удалял и `make clean-test-data` не
  затрагивал (он чистит только объекты из `file_storage`).

**Open questions:**
- Нужен ли админу выбор целевого S3-ключа/слага примера, или генерировать
  автоматически из category+from+to (как сейчас `examples/<category>/
  <from>-to-<to>.<ext>`)?
- Что при пометке примером, если для этой категории пример уже есть —
  заменять или разрешать несколько на категорию?
