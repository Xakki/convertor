# Приватность публичного API

## Что видит анонимный клиент

Публичные операции можно вызвать без регистрации и без браузерной cookie. Для
ограничения квоты и проверки владельца сервер связывает запросы только с
непрозрачным техническим идентификатором. Исходный сетевой адрес не является
данными продукта и не возвращается клиенту.

Идентификатор выбирается на доверенной границе прокси. Переданные клиентом
заголовки, которые пытаются выдать себя за адрес прокси, не меняют владельца
запроса.

При наличии более сильной аутентификации порядок такой:

1. JWT зарегистрированного пользователя;
2. персональный API-токен;
3. действительная cookie `guest_id`;
4. ограниченный анонимный доступ без cookie.

## Границы доступа

Анонимный клиент получает только ответ и ресурсы своей текущей операции.
Общий список истории по сетевому адресу не предоставляется: пользователи,
которые находятся за одним NAT или VPN, не получают историю друг друга.
История, повтор, удаление, платежи, профиль и административные операции требуют
соответствующей пользовательской или административной аутентификации.

Операции AI и видео требуют входа. Для остальных разрешённых публичных операций
действуют обычные проверки квоты, владельца и ограничения частоты запросов.

## Хранение

Анонимная identity деактивируется, а её непрозрачный идентификатор очищается
сервисом очистки по полю `createdAt`, когда строка старше порога в 30 дней.
Этот сервис не удаляет записи конвертаций. Файлы и записи, связанные с
конвертацией, очищаются отдельным сервисом по фактическому retention тарифа;
для гостевого тарифа сейчас настроено **24 часа**. Эти сроки не следует
смешивать и не являются обещанием удаления всех данных одним процессом.

В ответах API, сохранённых данных, сообщениях об ошибках и пользовательской
документации нет исходного сетевого адреса или значения, используемого для
защиты идентификатора.

Эта страница описывает пользовательский контракт: настройки доверенной границы,
значения защиты и внутренние сетевые адреса не публикуются.
