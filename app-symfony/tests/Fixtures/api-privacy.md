# Приватность публичного API

Анонимные публичные операции используют непрозрачный технический идентификатор
только для квоты и проверки владельца. Исходный сетевой адрес не является данными
продукта и не возвращается клиенту.

Идентификатор выбирается на доверенной границе прокси. Переданные клиентом
заголовки не меняют владельца запроса.

Приоритет аутентификации: JWT, персональный API-токен, действительная cookie
`guest_id`, затем ограниченный анонимный доступ без cookie.

Анонимный клиент получает только ответ и ресурсы своей текущей операции. Общий
список истории по сетевому адресу не предоставляется; пользователи за одним NAT
или VPN не получают историю друг друга. История, повтор, удаление, платежи,
профиль и административные операции требуют соответствующей аутентификации.
Операции AI и видео требуют входа; для остальных публичных операций действуют
проверки квоты, владельца и ограничения частоты запросов.

Анонимная identity деактивируется, а её непрозрачный идентификатор очищается
сервисом очистки по полю `createdAt`, когда строка старше порога в 30 дней.
Этот сервис не удаляет записи конвертаций. Файлы и записи, связанные с
конвертацией, очищаются отдельным сервисом по фактическому retention тарифа;
для гостевого тарифа сейчас настроено **24 часа**. Эти сроки не следует
смешивать и не являются обещанием удаления всех данных одним процессом.

В ответах API, сохранённых данных, сообщениях об ошибках и документации нет
исходного сетевого адреса или значения, используемого для защиты идентификатора.
